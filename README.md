# 语义通信研究项目

这个项目想回答一个问题：**当通信资源有限时，怎样把任务真正需要的信息传给对方？**

我们尝试把知识图谱用于通信过程。发送端根据当前任务，从已有知识中挑出相关内容；接收端维护自己的知识副本，并在需要时同步变化。项目通过本地模拟和实验脚本，观察不同选择对任务完成、传输开销和通信环境适应性的影响。

这是一份持续完善的研究代码，不是开箱即用的通信产品。仓库中的实现和辅助工具用于学习、复现与进一步探索。

## 这个项目包含什么

- **任务相关的信息选择**：使用关键词识别任务意图，在知识图谱中寻找相关内容，并构建较小的连通子图。
- **收发双方的知识对齐**：模拟接收端知识落后于发送端的情况，比较不对齐、完整重传和增量对齐等方式。
- **通信过程模拟**：在本地模拟信道和资源选择，观察任务效果与传输开销之间的关系。
- **实验与绘图辅助**：提供评估、数据检查和结果可视化入口，便于查看已有实验的表现。

当前意图识别采用确定性的关键词匹配，不依赖大语言模型 API。云端和边缘端的行为在本地模拟，不需要部署真实服务器。

## 如何开始

项目主要使用 Python、PyTorch、NumPy、SciPy 和 Matplotlib。先安装依赖：

```bash
python -m pip install -r requirements.txt
python check_env.py
```

`torch_geometric` 的安装方式需要与本机 PyTorch 和 CUDA 版本匹配。完整实验还需要准备相应的知识图谱数据；仓库里的一些默认数据路径来自开发环境，运行前请按自己的位置调整。

例如，准备好 WN18RR 数据后，可以运行一个较短的调试训练：

```bash
python train.py --mode debug --epochs 8 --device cpu --kg-dir /path/to/WN18RR
```

把 `/path/to/WN18RR` 替换为包含项目所需知识图谱文件的目录。数据、依赖和设备配置不同，运行结果也可能不同。

## 代码在哪里

| 目录 | 主要内容 |
| --- | --- |
| `agents/` | 任务意图、知识选择与策略相关实现 |
| `models/` | 项目使用的模型组件 |
| `env/` | 信道与交互环境 |
| `experiments/` | 实验评估、统计与绘图入口 |
| `research/` | 按研究主题整理的辅助代码与资料 |
| `tests/` | 测试与基础检查 |
| `config/` | 模型、信道和训练配置 |

部分绘图与检查脚本依赖本地实验数据；相关数据、模型权重和其他未公开材料并不一定包含在仓库中。查看脚本的输入路径后再运行。
