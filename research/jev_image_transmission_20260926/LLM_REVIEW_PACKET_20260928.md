## 1. 一页概览

### 1.1 核心想法

> 接收端根据自己还缺什么信息，以及获得这部分信息的通信可靠性和代价，选择下一轮补传哪个区域或停止；目标是在有限资源下减少严重重建失败。

最初灵感来自 computer-use：每次都传整张清晰截图可能浪费资源。接收端通常已经理解大部分画面，只需要补看一个影响下一步操作的区域。

研究已收敛到**静态自然图像、128×128、两轮传输**。当前不执行桌面操作，不研究语言推理，不做视频帧间差分。

### 1.2 当前实际方案

1. 冻结 DCAT，用 C128 传首轮全图。
2. 从接收端重建图提取低层统计和视觉损伤描述。
3. 官方 Jev 或 Visual Jev 输出六个候选动作的决策概率。
4. 小型网络将可见信息及模型输出映射为各动作的预计 MSE 改善。
5. 选择一个象限、全局增强或停止。
6. C64 独立编码增强内容，与首轮固定等权融合。
7. 分别评价固定时刻选区效果，以及计入实测决策等待后的信道回放结果。

### 1.3 三个必须同时看到的事实

| 事实 | 当前证据 |
|---|---|
| 官方 Jev 和 Visual Jev 可以实际运行 | 真实 API 请求、本地视觉推理和端到端小试均已完成 |
| 当前裁剪增强 codec 的上限不理想 | 开发集即使由知道真实答案的 oracle 选区，仍比等载荷单轮 C192 低约 0.90 dB |
| 原始 Jev 没有表现出有效选区 | 32 状态中，官方成功响应全部选全局增强，Visual Jev 只选全局或停止 |

所以目前是“可以运行下一轮验证”，不是“已经证明方法有效”。

## 2. 背景、动机与最初的三个想法

早先考虑过知识图谱/推理型语义通信；本方向已经转向图像传输，旧 KG 项目的 STATE_DIM、TransE、GAIL 等不参与本方案。

从 computer-use 得到三个想法：

- 首次给全局概览，后续只补信息。
- 按当前任务需要分配区域，而非只按像素变化或显著性分配。
- 简单决策使用轻量模块，复杂情况再升级模型。

例子：远程打开 VS Code 项目时，文件夹路径框中的一个字符可能比大片背景重要；光标闪烁虽然变化大，却未必值得补传。这个例子说明“变化、显著性、信息缺口、补传收益”不是同一个概念。

**但当前自然图像实验没有操作任务、路径识别目标或任务成功率。** 这个例子只提供动机，不能作为自然图像重建实验的证据，也不能让当前方法自动获得“任务驱动”的身份。

“delta”原本有两种含义：

1. 同一幅图的渐进增强：第一版采用这一方向的简化近似。
2. 相邻帧差分：未实现。发送端上一帧原图与接收端受噪声重建的上一帧不同，版本号不会消除参考内容差异；需要状态同步或可独立解码的更新。

轻重模型级联、错误弹窗触发全局刷新、多轮连续控制，目前都只是后续想法。

## 3. 为什么考虑 Jev、Visual Jev 和 Laya

### 3.1 官方 Jev

使用 TypeSafe 直连，固定模型 ID `jev-1.13.0`。它接收文本/JSON，提供 Choice、Score、Noul 等结构化判断。官方版本的图像理解需要外部视觉前端；本项目没有微调官方模型。[模型说明](https://docs.typesafe.ai/models)、[API 文档](https://docs.typesafe.ai/api)

本方案实际用一项六选一 Choice，以及五项“该增强动作是否可能降低整图 MSE”的 Noul。每状态合在一次请求中。精确预算和时间运算由代码执行。模型概率仅作特征，不视为已校准的通信成功率；confidence 也不等同于质量改善概率。[confidence 定义](https://docs.typesafe.ai/confidence)

### 3.2 Visual Jev

这是第三方论文/代码的视觉决策模型，不是 TypeSafe 官方视觉版。当前使用作者的 Qwen3-VL-4B 底座与 answer-SFT LoRA，沿用候选项读出；权重冻结。[论文](https://arxiv.org/abs/2609.25845)、[作者代码](https://github.com/guanxuyu-sv/Visual-Jev)、[适配器](https://huggingface.co/guanxuyu/visual-jev-4b-answer-sft)

作者视觉任务的成绩与共享图像上下文技术，只证明其原论文设置下的能力，不能移植成无线选区准确率。批量问题的摊销时间也不能当成一次在线控制的完整延迟。

已固定的版本：

| 资产 | 不可变版本 |
|---|---|
| Visual Jev 作者代码 | `a392eaedfa41adae348f9767b55c0f54b3a13b57` |
| Qwen/Qwen3-VL-4B-Instruct | `ebb281ec70b05090aa6165b016eac8ec08e71b17` |
| guanxuyu/visual-jev-4b-answer-sft | `7a3f1bb0d8f7bfbbd8514d968ab7de3518849c8d` |

本机软件/硬件不同于作者实验，属于固定公开权重的本地移植推理，不是精确复现其整套训练与排行榜结果。

### 3.3 Laya

Laya 是最早考虑过的开源文本决策候选。当前模型卡列出 ModernBERT 系列等文本检查点，并支持类似 Jev 的结构化决策接口；它可作为同描述输入的本地对照。其自报跨模型成绩使用的样本和实验设置不完全相同，不能直接推出优于官方 Jev。[Laya 模型卡](https://huggingface.co/convaiinnovations/laya)

**当前没有下载、集成、微调或测试 Laya，它不在已准备的完整矩阵中。** 如果评审认为本地文本决策器是必要强对照，应先加入并重冻协议。它仍需要视觉描述前端，不能自动消除全部视觉计算成本。

### 3.4 模型必要性问题

如果前端只产出四个模糊程度分布，简单 MLP 可能已经足够；如果需要先调用 4B 视觉模型，必须证明再调用文本 Jev 有独立收益。模型较新只是研究动机，不能作为贡献本身。

## 4. 研究问题与拟议创新

最初较完整的研究问题：

> 在相同总通信/能量上限与截止时间约束下，接收端能否结合信息缺口、CSI 老化和实际等待，预测局部增强的价值，并减少严重重建失真？

“价值”应是实际补传后整图失真的下降，而不是显著性、模型自信或当前误差的替代说法。当前最重要的假设是：

| 假设 | 需要的证据 | 目前状态 |
|---|---|---|
| H1：预测补传收益优于只预测当前损伤 | 与重要性、仅不确定性、固定/随机动作比较 | 待完整学习实验 |
| H2：Jev 提供了描述前端之外的信息 | 同前端、同训练机会，移除 Jev 特征后的配对比较 | 未证明；原始决策小试不支持直接增益 |
| H3：CSI 年龄有独立价值 | 去掉年龄，保持其余输入/codec一致 | 已准备消融，未正式运行 |
| H4：停止决策能避免有害增强 | 同一收益预测器强制增强对照 | 已准备消融，未正式运行 |
| H5：计入全部相关代价后系统仍受益 | 等上限单轮 C192 与真实等待回放 | 目前 codec 的开发结果不利 |

H3 还需要解释机制：若年龄只是所有区域共同乘一个正数，不能改变区域排序，只能影响停止；不能据此宣称老化感知选区。

**明确不把 ROI、反馈、差分、使用 Jev、概率阈值、调用缓存单独作为新贡献。**

## 5. 实际编码、动作与融合

### 5.1 传输设置

- 静态 RGB 图像，128×128。
- 底层 DCAT 使用冻结公开权重，已准备 C64、C128、C192。
- `C` 是本实现的潜在通道宽度参数；对应载荷约为 `32C` 个复信道符号，不是图像分类类别数。
- 首轮 C128：4,096 个载荷符号；增强 C64：2,048 个；单轮 C192：6,144 个。

候选动作集合：

`A = {左上、右上、左下、右下、全局增强、停止}`。

### 5.2 简化 ROI codec

发送端裁剪原图一个 64×64 象限，双线性放大为 128×128，用 C64 独立编码，接收端解码后缩回 64×64。选中区域按以下方式融合：

`x_hat_final[r] = 0.5 * x_hat_base[r] + 0.5 * x_hat_enhancement[r]`。

区域外保留首轮图。全局增强则对整图等权融合；停止保留首轮。主实验固定 α=0.5。开发时还单独看过 α=1，未以 oracle 在两种融合间择优。

这不是经过端到端训练的渐进特征编码，也不是已有 ROI 反馈方法的原样复现。它只提供一个低成本检验选区空间的共同动作接口。独立裁剪编码、放大再缩小及固定混合，可能本身就是效率瓶颈。

## 6. 实际部署输入与收益学习器

### 6.1 三条决策路径

```text
首轮接收图
 ├─ 每象限低层统计 ──────────────────────────────┐
 ├─ 原始 Qwen 输出每象限可见损伤分布 → 官方 Jev ─┤
 └─ Visual Jev / 原始 Qwen 直接六动作评分 ────────┤
首轮可用 SNR、CSI 幅度、CSI 年龄 ─────────────────┤
                                                 ↓
                              小型收益预测网络 → 一个动作
                                                 ↓
                           资源/截止检查 → C64 增强或停止
```

官方 Jev 的视觉描述前端不是人工标注：原始 Qwen 在接收图上对每象限回答“low / noticeable / severe / uncertain”，保留四类概率。没有原图输入，没有开放式物体语义描述，也没有 task intent。

视觉模型接收首轮浮点重建量化为 8-bit RGB 后放大到 448×448 的图。原始 Qwen 与 Visual Jev 使用相同图像和动作问题。文本对照使用同样描述和固定灰色图像，避免把原图信息再次偷偷提供给文本对照。

### 6.2 正式输入槽位

统一 61 维槽位，不用的槽位置零：

| 槽位 | 来源 | 维数 |
|---|---|---:|
| 图像统计 | 每象限均值、标准差、梯度、Laplacian 方差、灰度熵、裁剪像素比例 | 24 |
| 首轮信道状态 | 已知 SNR、最近可见 CSI 幅度、最后首轮符号的 CSI 年龄 | 3 |
| 描述 | 四区域 × 四损伤类别概率 | 16 |
| 官方 Jev | 六动作概率、五个正收益 Noul、一次 API 失败标记 | 12 |
| 视觉决策特征 | Visual Jev 或原始 Qwen 六动作概率 | 6 |

每个方法只启用对应子集，不是把所有来源都加在一起。数值模型、描述模型、官方 Jev 模型、Visual Jev 模型、Qwen 模型有相同的网络宽度与名义参数数目；置零输入的有效信息容量不同，不能说信息量完全相同。

正式版的所有基础模型提示词**不含 SNR、CSI 幅度、CSI 年龄**；它们只进入小网络。因此年龄消融不会从 Jev 提示词直接读回被移除的年龄。接收图受老化损伤这一自然影响仍然存在。

### 6.3 监督目标与训练

在训练数据离线枚举动作，用真实原图计算：

`g(a) = (MSE_base - MSE_after_action_a) / max(MSE_base, epsilon)`。

训练时截断到 [-4,1]，用 MSE 回归；报告预测误差时使用未截断真实目标。停止的预测收益固定为零，按最大预测收益选择动作。网络为 `61 → 64 → 64 → 6`，两层 ReLU。

仅不确定性对照采用四输出网络，预测各区域当前 log MSE，再选择预测误差最大的区域。

三个训练种子 11/29/47；Adam、lr=0.001、最多 300 轮；验证损失连续 25 轮不改善停止。归一化只用训练集，轮数只用验证集。小网络在 CPU 训练，DCAT/Qwen/Visual Jev 不训练。

### 6.4 信息隔离

真实原图、真实误差和未来信道可以离线生成监督，但不能出现在部署输入。`states/` 与 `labels/` 分开；基础模型只读 states 和接收图；学习脚本在训练/选择阶段只打开训练和验证标签；选完测试动作后才汇总测试标签。

原图完好地存于发送端，不先传给接收端再裁剪；否则裁剪只减少推理输入，不能称为节省图像无线传输。

## 7. 目标与当前实现的关键差距

这一节尤其需要评审。历史构想有些表述强于实际代码。

| 最初目标 | 当前实际 | 结论边界 |
|---|---|---|
| 执行前按最新状态重估各动作收益 | 基于首轮状态选一次动作；回放等待后刷新导频并执行原动作 | 尚未实现执行时重新选区/重评分 |
| 等待、剩余预算、截止时间进入收益预测 | 61 维特征没有这些字段；由回放层做可行性检查和超时回退 | 不能宣称已学到等待代价最优策略 |
| 当前 CSI 与 CSI 年龄共同刻画下一轮信道风险 | 学习器看到首轮末尾状态；回放增强前强制新导频 | 当前年龄更可能解释首轮损伤，而非第二轮长期过时 CSI |
| 减少严重失败的风险敏感优化 | 训练目标是相对 MSE 改善；失败率仅为评测指标 | 尚无独立尾部风险损失/概率校准 |
| 同一接收状态下多条未来分支估计期望收益 | 当前重复会改变首轮状态和未来噪声；每状态保存一条实现的动作结果 | oracle 是事后上界，不是可知的条件期望最优动作 |
| 多轮、可变增强强度和历史记忆 | 固定两轮、固定 C64 和四象限 | 不支持完整序贯决策主张 |
| 轻量快环、困难样本升级强模型 | 各模型分支独立评测，没有在线级联 | 不能宣称已实现按难度升级 |
| 官方 Jev 离线辅助、本地低延迟部署 | 官方特征分支测试时仍调用 API | 当前不是蒸馏后的免 API 方法 |

**当前更准确的定位：冻结 codec 下的接收端质量收益预测与动作选择，加上实测等待的系统代价回放。**

## 8. 已完成的真实预实验

### P0：接口连通性

8 次人工构造文本请求，全部 HTTP 200，返回 jev-1.13.0；Choice/Score/Noul 均可调用。中位客户端耗时约 1.43 秒。只是接口验证，不能当图像准确率。

### P1：codec 与 oracle 空间

Kodak 01–16；2 SNR × 2 年龄档 × 3 轨迹窗口 × 2 基础码率，共 384 个首轮状态。主分析 α=0.5：

| 基础+增强 | 开发集最佳固定动作 PSNR | oracle PSNR | 单轮等载荷 PSNR | oracle 比单轮 |
|---|---:|---:|---:|---:|
| C64+C64 | 22.552 | 22.688 | 24.464（C128） | −1.776 dB |
| C128+C64 | 24.392 | 24.706 | 25.602（C192） | −0.896 dB |

C128+C64 相对最佳固定动作，oracle 高约 0.314 dB，平均 MSE 低 6.96%；但仍低于单轮。这里仅同前向载荷，尚未扣除真实 API 等待和控制开销，因此已是对两轮有利的比较。α=1 的独立结果也未达到单轮。

原来预先写过的门槛是：oracle 应有至少 5% 的固定策略 MSE 改善，并至少匹配等载荷单轮。C128 通过前半个门槛，**未通过后半个门槛**。

固定动作集与执行时刻下，任何选择器在这个开发样本上的实现 MSE 都不可能优于逐状态取最小 MSE 的 oracle。因此不能指望只换 Jev 选择器就越过这个已观察的平均失真上限。这个结论不外推为“所有新数据、尾部指标或不同 codec 均不可能改善”。

探索性尾部观察：旧 CSI 的 96 个 C128 状态中，oracle 的 20 dB 以下失败为 5/96，单轮为 6/96；第 5 百分位 PSNR 约 19.998 vs 19.655 dB。只差一个失败事件，阈值在当时未预注册，不能据此宣称可靠性优势。

## 10. 公平资源与时间评估

### 10.1 两条轨道

**固定时刻诊断**：首轮结束后固定 0.125 ms 执行增强，所有选择器查同一动作结果表，隔离选择质量。真实决策耗时另列。它不表示 API 在 0.125 ms 内完成。

**实测等待回放**：记录本地前端、官方服务、小网络的实测耗时；各方法按自己的耗时推进信道。返回后等下一个周期导频并收费，再在新的信道时刻执行所选动作。不是继续使用固定时刻的增强重建结果。不同分支的无关计算时间不算到该方法上。

但当前回放只改变执行时刻与传输结果，不用新的 CSI 重选动作；训练标签也仍来自固定时刻表，存在训练目标与慢模型实际执行条件不一致的问题。

### 10.2 预算

共同上限 6,656 复符号：

| 项目 | 计费 |
|---|---:|
| 基础载荷 C128 | 4,096 |
| 增强载荷 C64 | 2,048 |
| 每次图像头部 | 32 |
| 请求反馈 | 64 |
| 每次实际观测导频 | 64 |

总预算包含这些前向与反向项，报告未用预算。单轮 C192 载荷 6,144，加它自己的头部/导频。由于只有离散公开码率权重，是**共同上限**比较，不是每种方法精确等消耗；没有训练一个刚好用满剩余预算的新单轮模型。

反馈假设独立 1% 包擦除，同状态各策略共享擦除抽样；头部假设可靠，未实现具体 FEC。无线反馈错误与互联网 API 失败是两个独立概念。

RF 能量按每复符号单位发射能量计算，不包含 CPU/GPU、API 服务能量。官方 API 另走服务网络；当前无线符号预算不包括该网络的全部字节/包/能耗，不能称为已完成所有网络资源的联合核算。

### 10.3 截止与 CSI

截止时间 2,500 ms。超时保留首轮图；晚发增强仍计实际资源。API 等待期间不免费读取中间导频，等待结束后为新导频支付等待和资源。

当前将完整首轮 codec 调用时间保守地放到接收后等待，并加增强 codec 的完整调用耗时；没有分别准确测量编码、收发、解码各硬件阶段。这是声明假设的仿真，不是硬件无线端到端实测。

由于补传前刷新 CSI，模型数百毫秒到数秒的等待远大于毫秒级信道更新，旧信道相关性和年龄究竟还能影响什么，是需要评审的机制问题。

## 11. 指标与统计计划

- PSNR、MSE、LPIPS（normalize=True），统一 [0,1] RGB 范围。
- 最优动作命中率、与最优 MSE 相差不超过 2% 的比例、PSNR 选择损失。
- PSNR 第 5 百分位，20 dB 以下失败率。20 dB 是看过开发结果后、正式结果前固定，不能追称最初预注册。
- 预测相对 MSE 收益与真实收益的误差。
- 载荷、头部、反馈、导频、未用预算、单位 RF 能量、决策耗时、仿真时延、截止失败。
- API 失败保留；token 仅按实际返回 usage 汇总，网络失败时远端用量未知。

主比较：官方 Jev 学习器 vs 同描述前端学习器。次比较：Visual Jev vs Qwen；年龄消融；停止消融；单轮 C192。

三训练种子先在同一状态取平均，再按 UDIS 组件或 DIV2K 图像做 2,000 次配对 bootstrap；另报每种子结果。重复动作/信道样本不当作独立图像。区间未做多重比较调整，无稀有事件功效保证，不能择显著子组证明总体有效。

共享传播轨迹还会造成跨图像依赖，仅按图像聚类未必捕获这部分不确定性；因此应将区间解释为给定这些轨迹条件下的结果。UDIS、DIV2K-A9、DIV2K-A1 单独报告。

当前代码在回放报告中仍用“固定时刻 oracle”衡量动作准确率/选择损失，这些字段不是该慢模型执行时刻的新 oracle；实际回放质量需要另看。

## 12. 直接前作与新颖性边界

以下是已识别的比较对象，不是穷尽性 SOTA 清单。基础机制从官方页面/论文条目核对；ROI 全文仍未取得。新 Jev 条目按预印本记录，不推断其已录用。

| 来源 | 与本方案重叠的机制 | 本方案需要额外证明 |
|---|---|---|
| [DeepJSCC-f](https://arxiv.org/abs/1911.11174) | 利用反馈改善图像传输 | 不能把“有反馈”本身写成创新 |
| [JSCCformer-f](https://arxiv.org/abs/2306.09101) | Transformer 与信道反馈结合 | 接收端动作价值机制超出一般反馈增强的证据 |
| [FAST](https://arxiv.org/abs/2401.14614) | 特征重要性、信道预测、时空分配 | 为什么接收端可预测的边际收益优于已有重要性适配 |
| [DCAT](https://arxiv.org/abs/2509.11243) | 动态信道、时变衰落与 CSI 老化下图像传输 | 冻结已有能力，隔离新增决策的作用 |
| [ROI-Based Image Transmission With Channel Feedback](https://ieeexplore.ieee.org/document/11352529/) | ROI 与反馈结合；目前只核对过公开摘要 | 必须补全文逐机制比较，尚不能排除高度重叠 |
| [Communication-Efficient Multi-Modal Edge Inference via Uncertainty-Aware Distributed Learning](https://arxiv.org/abs/2601.14942) | 不确定性引导额外信息请求 | “不确定就补信息”不构成独立首创；任务不同也不自动新颖 |
| [Fast Intent-Driven Service Orchestration with Jev for 6G Edge Networks](https://arxiv.org/abs/2609.23136) | Jev 判断、数值调度、真实判断等待 | 用 Jev 做通信控制、判断与调度分离、计入等待已经有直接先例 |
| [JEV-as-a-Judge](https://arxiv.org/abs/2609.26550) | 信心接受/升级机制 | 仅以置信度阈值做升级或停止不足以构成新意 |
| [Visual Jev](https://arxiv.org/abs/2609.25845) | 从共享视觉上下文做候选决策 | 本任务的独立收益、成本及迁移有效性必须自己测 |

因此，目前可以提出的差异只是一个**待证假设**：把接收端可见的损伤证据与链路状态映射为局部增强实际质量收益，并检验其在资源/时限下的作用。是否足够新颖，必须由全文比较与实验共同判断。

## 13. 请重点审查的薄弱点

1. **codec 上限先失败。** 在已观察开发集，oracle 也输给单轮。大规模训练选择器是否把算力花在了错误瓶颈？
2. **原始模型几乎不选区域。** 可能是任务迁移失败、描述信息不足、选项先验、提示词或 codec 动作本身无效；目前不能区分。
3. **官方 Jev 的必要性。** 同描述 MLP、原始 Qwen 已有输入信息；Jev 是否只是昂贵的非线性特征变换？应如何证伪？
4. **当前不是执行时自适应重估。** 收益网络没有新 CSI、等待、预算输入，刷新导频后不重选，不能将最初完整愿景写成已实现方法。
5. **训练目标与运行条件不一致。** 固定短间隔标签训练的动作选择器，被直接用到经历数百毫秒/秒级等待并刷新 CSI 的条件。
6. **尾部目标未直接优化。** 平均相对 MSE 回归不能自动支持严重失真风险建模的表述。截断严重负增益可能改变对有害动作的惩罚。
7. **标签与 oracle 不确定性。** 每个接收状态缺乏独立未来分支；最优动作可能受未来噪声主导。应估计可预测上限与 oracle gap。
8. **预算/时间账本需代码复核。** 导频、头部是否与信道时间轴一致？超时前是否真的发出反馈？`feedback_sent` 当前在截止检查前赋值，可能给未发送的反馈收费；应审计后再作精确成本主张。
9. **截止回退语义。** 若解码完成后才超时，资源已消耗但质量回退首轮是否符合所定义应用？单轮与停止策略是否采用同一计时起点？
10. **强对照不足。** 现有统一数值实验没有复现直接 ROI 反馈前作；固定区域仅显式列右上，是否还应列全部四区域、训练集选出的最佳固定策略，以及 Laya 或更强的小型回归基线？
11. **泛化和统计。** 两个信道场景、共享轨迹、开发后选阈值、公共视觉预训练与有限组件划分，限制结论强度。
12. **协议适用场景。** 官方 API 中位总决策接近 2 秒。应明确是延迟宽松静态图像服务，而非毫秒级无线控制。

上述条目包含已知实现事实与待审计问题；“可能”事项不是已经证实的代码缺陷。此前工程 READY 只表示可执行，不表示这些科学/计量问题全部通过独立审查。

## 14. 可供评审选择的下一步方向（尚未实施）

### A. 先修 codec，再研究选择器

尝试更合理的基础/增强分配、独立增强特征或可训练融合，先使同预算 oracle 有足够空间。若做残差编码，必须明确发送端如何知道接收端参考，不能默认两端参考一致。不能用理想原图替换上界冒充实际传输收益。

### B. 先做小规模可预测性诊断

固定首轮状态，采样多条合法未来分支，比较预期最优动作和实现 oracle。用数值/描述小网络先检查可预测收益，再判断追加 Jev 是否有价值；若简单模型已接近可达上限，则缩小 Jev 主张。

### C. 真正实现执行时收益更新

把当时可用 CSI、预计等待/截止、预算与动作成本接入预测器；训练/评估都采用一致的时间协议。评审需判断这是必要修复还是会过度扩大问题。

### D. 调整 Jev 的角色

官方 Jev 可作为离线辅助信号或教师，部署本地模型；Laya 可作同描述本地对照；Visual Jev 可作独立视觉分支。以上都需要新实验，不能把当前在线特征调用改名为离线蒸馏结果。

### E. 如果任务不适合，缩小或结束主张

可以转成“决策模型在图像补传中的失效与成本评测”，或回到最初有明确任务信息缺口的截图/OCR场景。但都应新增真实任务与指标，不能用自然图像重建结果替代桌面操作成功率。

不要求评审选择能保留 Jev 的方向；请优先选择有证据、成本可控且能被证伪的研究问题。
