## 2. Phase 0 已完成的 CPU 诊断

### 2.1 数量与比较口径

输入为 P1 的 4,608 行：384 状态 × 6 动作 × 2 个 alpha。主分析固定 alpha=0.5；每个基础码率分支各 192 状态。逐条检查动作完整性、重复项、有限正 MSE、PSNR 与 MSE 一致性。

| 指标 | C64+C64，192 状态 | C128+C64，192 状态 |
|---|---:|---:|
| 等载荷单轮对照 | C128 | C192 |
| oracle 选择象限 | 52 / 192 = 27.08% | 112 / 192 = 58.33% |
| oracle 选择全局 | 138 | 55 |
| oracle 选择停止 | 2 | 25 |
| 全局 MSE ≤ 最佳象限 MSE | 71.88% | 28.65% |
| 全局 MSE ≤ 1.01 × 最佳象限 MSE | 73.96% | 29.69% |
| 最佳象限比 global/stop 最优者再降低 >1% MSE | 47 / 192 | 104 / 192 |
| best-fixed 平均 PSNR | 22.5517 | 24.3919 |
| 六动作 oracle 平均 PSNR | 22.6878 | 24.7055 |
| 等载荷单轮平均 PSNR | 24.4638 | 25.6020 |
| oracle 相对 best-fixed 的平均 MSE 降幅 | 3.576% | 6.958% |

两个分支均未触发用户给定的停止条件。象限动作在这个开发协议中有价值，但不能据此推出 Jev 能学会选择，或两轮 codec 已值得使用。当前 C128 六动作 oracle 仍低于 C192 约 0.8965 dB。

### 2.2 +0.3137 dB 不能只拆成“停止”与“选区”

这里还有“全局增强”这个独立动作。采用明确、可复算的嵌套顺序：

| C128 分支动作集合 | 平均 PSNR | 相对上一步增益 |
|---|---:|---:|
| 固定右上象限，即 best-fixed | 24.3919 | — |
| 真值选择四象限之一 | 24.5598 | +0.1680 dB |
| 再允许选择全局增强 | 24.6872 | +0.1274 dB |
| 再允许停止 | 24.7055 | +0.0183 dB |

三项之和为 +0.3137 dB。**这是一种顺序相关的增益分解，不是唯一的因果贡献分配。** 在另一条比较链中，global/stop 二选一 oracle 为 24.5720 dB，增加四象限后再增加 0.1336 dB。由此也能确认象限价值不只是停止效果。

C64 的 best-fixed 是 global，不能把从固定象限出发的分解冒充其相对 best-fixed 的 +0.1361 dB。

### 2.3 免费追加的 A1 诊断：单标量融合的真值上界

原脚本先裁剪基础图和增强图，再作 alpha∈[0,1] 的凸组合。对固定状态、固定动作：

`D(alpha) = D0 + b*alpha + a*alpha^2`

其中 `a = 2*D1 - 4*D0.5 + 2*D0`，`b = D1 - D0 - a`。
`D0` 来自 stop，另两点已保存在 JSONL。因此无需再跑模型，即可用真值计算逐状态、逐动作的最佳 alpha，再选动作。

| 指标 | C64+C64 | C128+C64 |
|---|---:|---:|
| 联合选择动作和单标量 alpha 的 oracle PSNR | 22.9189 | 24.7765 |
| 对等载荷单轮的差值 | −1.5449 dB | −0.8256 dB |

结论：**若 A1 仅学习每个状态/动作的单个凸融合系数，就不能跨越当前门槛。** 原规划中的小 CNN 可输出新的融合图，不属于这个函数族，因此不能用此结果否定 CNN 融合、逐像素融合或 A2。这个新增诊断属于事后上界分析，不是部署方法或泛化结果。

### 2.4 Track A 的保留条件

- A1 若保留，应明确是小 CNN 的图像修复/融合能力；不要再花半天训练仅输出一个 alpha 的模块。
- A2 的条件解码器可以使用接收端的第一轮重建。发送端 enc2 只能使用原图、区域请求及已约定反馈；若编码相对接收端有噪重建的残差，必须额外解决发送端如何获得该参考及其开销。
- 主线 C128 的门槛使用这 192 状态与 C192；C64 作为独立分支对 C128。原文“384 状态全部 C128 基础”需纠正。
- P1 已多次用于判断和改进，只能作为开发门槛。最终结果须有独立图像与信道留出集。
- `suite_data.json` 的 512 图是当前项目从所准备 UDIS 图像中划出的训练子集，不能不加说明地称为作者官方训练划分。
- 三天是资源上限，不能保证新 codec 收敛。即使 oracle 过门槛，下一步仍须验证可部署选择器，而不是立刻启动完整 Jev 矩阵。

## 3. Track B：必须先修正 CP 的解释

官方本地代码的行为明确：

- `inference.py:67–71`：开关改变 checkpoint，分别加载 `with_CP_C128` 与 `without_CP_C128`。
- `inference.py:104–107`：打开 CP 时读 `CSI` 真值，关闭时读 `NoPred`。
- `inference.py:135–138`：CP 分支把 TX/RX 年龄置零，直接使用 `csi_txrx` 作为编码侧 CSI，覆盖先前 `CSI_casual` 的结果。
- `readme.md:99` 将开关说明为假定理想信道预测。
- `reproduction/common.py:62–75` 的本地复现封装沿用相同含义。

因此 `CSI_casual` 是不使用理想预测时，用于限制编码端可见导频的辅助逻辑；它本身不是论文提供的可训练 CP 模块。`NoPred` 才保存最近导频保持序列。代码入口确实可以扩展，但研究定位应为**在 DCAT 中实现并评估实际因果 CSI 预测**，而不是“改进作者已有的 hold 型 CP”。[官方仓库](https://github.com/PKU-PCNI/SoM-DCAT)

历史报告中的均值差确实是：

| 速度 m/s | 2 | 6 | 10 | 15 | 21 |
|---|---:|---:|---:|---:|---:|
| 理想分支减非理想分支，dB | 0.5486 | 0.6755 | 0.8018 | 1.3505 | 2.2021 |

这些是**不同权重、CSI 可见性和年龄输入一起改变后的经验差距**；既不是同权重预测器的独立收益，也不是实际预测器的可达上界。原计划 B2“比 with-CP 基线再高 0.3 dB”尤其应改成“比同权重、同协议的 hold 基线高 0.3 dB”。

### 3.1 最小可归因比较

第一组固定 `without_CP_C128` 权重、相同图像/信道起点/噪声/资源，只改变合法 CSI 估计：hold、训练集拟合的 Wiener/AR、学习预测器。用真实 CSI 的诊断行应明确年龄/可靠性输入的处理，不能暗中把年龄也清零。

第二组可固定 `with_CP_C128` 重复上述比较，评估实际预测误差与理想 CSI 训练分布的失配。不要将两组 checkpoint 的差计入预测器贡献。历史“with_CP + 真值 + 零年龄”保留为作者理想配置参考。

适配器须分开处理：

1. `csi_gt`：物理信道真值，仅用于生成接收信号，绝不能被预测值覆盖。
2. `csi_encoder`：发送前可用信息产生的整段预测；不能使用传输途中尚未到达的导频。
3. `csi_txrx`：接收端估计，可随已到达导频更新；同时影响接收端条件输入与 ZF 均衡。

先做 TX-only、RX-only、两端联合三个消融。TX/RX 对未来信息的可见性不同，不能共享一个事后预测数组而默认因果。

### 3.2 NMSE 下降不保证重建改善

`net/Scoring_channel.py:80–81` 直接计算 `Y / CSI_ZF`；接近零的预测会放大噪声。零预测的 NMSE=1 是误差参照，不能直接用于该 ZF 除法。

`net/network.py:31–32, 63–75` 还存在 `pred_nmse_tx/rx`。`net/som_modules.py:148–167` 用年龄和速度预测 CSI 误差，再在注意力中调节 CSI 与 SNR 的权重。替换 hold 后，这个“年龄→误差”的关系也会变化。故 B2 必须检查：真实预测误差、原误差估计器的校准、均衡误差、排序效果与最终失真；不应把“预测值更新”当成完整适配。

若加入误差校准或稳定均衡，必须给 hold/Wiener 同等模块对照，并分别消融，避免收益实际来自额外均衡修复。

## 4. B0 的因果协议与统计边界

此次实读 A1/A3/A5/A7/A9 的 MAT：每条 128,000 个点，年龄步长 0.03125 ms；零年龄导频恰好 1,000 个、相隔 128 点，即 4 ms。`NoPred` 与最近导频的 CSI 完全一致，最大绝对差为零。

重新计算的 hold NMSE：0.033659、0.091636、0.156565、0.470687、1.133707，与历史报告一致。

因此：

- 一条轨迹只有约 4 秒、1,000 次导频观测；128,000 个细网格标签不是同等数量的独立观测。不能把全部细网格真实 CSI 当作预测器的可用历史。
- C128 对应 64 个时间位置，跨度约 2 ms。编码端的预测 horizon 必须覆盖“发送时已有年龄 + 图像传输时间”，不能只评估下一导频或统一的单步预测。
- 按连续时间块划分训练/验证/测试，保护间隔至少覆盖历史窗口与预测跨度；归一化、相关估计、阶数和正则只用训练/验证集确定。更换图像不会隔离信道训练与测试。
- 固定速度与 Case B 时变速度都应评估。要对新环境作推广结论，最终应有独立生成的信道轨迹；现有轨迹的非重叠片段只能支持较窄结论。
- “09-28 Wiener pilot”在本次检查的研究目录与 reproduction 代码中未找到可复算脚本。原规划转述的数值不作为已验证依据；B0 需重建并保存配置、数据分割与输出。

**genie-linear 的正确解释：**给定历史长度、horizon 和统计假设下，已知真实协方差的最优线性参考。如果协方差是从测试轨迹真值估计的，属于 oracle-statistics 诊断，不能混作可部署成绩。它不是一般非线性预测器的信息论界；“线性 oracle 无改善”不能直接推导“任何预测都不可能”。只有额外满足联合高斯等条件，才可建立对应的 MMSE 最优性。
